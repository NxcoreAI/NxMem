## Context

现有 `longmemeval-cli.ts` 将第一个位置参数解析为数据集路径，并把完整文件交给 `evaluateLongMemEvalDataset` 或 `evaluateLongMemEvalModelRuns`。评测核心内部也会直接从 JSON 加载全部样本；`clearLongMemEvalData` 已负责删除本地评测存储文件并按配置清理 Neo4j。CLI 需要在不改变默认全量评测和 HTTP 接口的前提下增加可组合的数据选择与清理命令。

## Goals / Non-Goals

**Goals:**

- 支持一个或多个 `question_id` 的精确评测，并在找不到 ID 时失败而不是静默降级。
- 支持按比例、种子生成确定性的 JSON 子集，保留原始样本结构，并使用该子集完成同一套跑分流程。
- 支持显式确认的数据库清理命令，复用已有清理函数，提供人类可读和 JSON 结果。
- 为参数校验、抽样复现、命令分派、退出码和清理结果增加测试。

**Non-Goals:**

- 不改变 LongMemEval 指标、答案生成、judge 或 ingestion 算法。
- 不修改原始数据集文件，不新增运行时数据库表或外部依赖。
- 不提供按复杂业务规则分层抽样的通用数据处理框架；仅保证按题型分层的稳定比例抽样。

## Decisions

1. **在 CLI 前置生成“有效数据集路径”**
   - 新增独立的数据集选择/切分辅助模块：读取 JSON 数组，按 `--question-id` 过滤，或按 `--ratio` 抽样并写入 `--output`（未指定时写入系统临时目录）。返回路径、原始/选中数量、seed 和题型统计，再把路径交给现有 evaluator。
   - 选择前置处理而不是给 evaluator 增加多套过滤参数，保持核心 API 与 HTTP 行为稳定；代价是子集需要一次额外磁盘写入。

2. **比例切分使用可复现的题型分层抽样**
   - `0 < ratio <= 1`，默认 seed 为固定常量；同一原始文件、比例和 seed 得到相同 question_id 集合。
   - 对每个 `question_type` 独立打乱，按 `floor(count * ratio)` 取样，并保证 ratio 小于 1 时每个非空题型至少保留 1 条；最终按原始文件顺序输出，避免改变数据语义。
   - 选择分层抽样而非全局随机抽样，以避免小规模跑分完全丢失题型；代价是严格样本数可能因“每类至少一条”略高于比例下限。

3. **CLI 使用子命令并保持旧用法兼容**
   - 保留 `eval:longmemeval [dataset]` 的默认全量行为；新增 `sample`、`split`、`clear-db` 子命令。`sample` 和 `split` 共享所有现有评测参数。
   - `sample` 可重复接受 `--question-id <id>`，也可接受逗号分隔值；另提供 `--sample-range <start>-<end>`，按原始文件顺序使用 1-based 闭区间。ID 选择与区间选择互斥，且二者都与 `--ratio` 互斥，避免选择语义不清。
   - `split` 要求 `--ratio`，可选 `--seed`、`--output`；默认输出到临时文件并在结果中报告路径，方便后续复跑。

4. **清理必须显式确认**
   - `clear-db` 默认拒绝执行，只有传入 `--yes`（JSON/脚本模式也同样要求）才调用 `clearLongMemEvalData`。
   - 清理期间不自动取消正在运行的 job；若 CLI 与服务共享存储，调用方需先停止评测。输出沿用 `LongMemEvalDataClearResult`，不泄露凭据。

5. **统一输出和退出码**
   - `--json` 输出单个 JSON 对象，包含 command、dataset/subset 元信息及 report/clear result；普通模式输出摘要。
   - 参数错误、样本不存在、比例非法、清理未确认和评测异常均以非零退出码结束，并将错误写入 stderr。

6. **提供 CI 严格模式**
   - `--ci` 作为显式模式开关，强制 `--json` 语义、关闭进度输出，并要求切分命令提供稳定的 `--seed`；禁止从 stdin 读取确认。
   - stdout 只输出最终 JSON；可选 `--result <path>` 将同一份 JSON 原子写入文件。退出码固定为：`0` 成功，`2` 参数/输入错误，`3` 评测执行失败，`4` 清理未确认或清理失败。
   - 选择显式 CI 模式而不是仅根据 `CI` 环境变量推断，避免本地 shell 和不同 CI 平台行为漂移；可兼容读取环境变量但不依赖它。

## Risks / Trade-offs

- [临时子集文件未清理] → 只在未指定 `--output` 时使用临时目录，并在评测完成后删除；JSON 结果保留路径前先确认文件是否仍可用，指定输出则不删除。
- [区间边界误解] → 在帮助和 JSON 元信息中明确 1-based、两端包含，并在越界或起点大于终点时返回参数错误。
- [原始数据集很大导致内存峰值] → 先沿用当前 JSON 数组加载方式，限制本变更范围；为切分模块记录文件大小和样本数，后续再评估流式解析。
- [清理与并发评测竞争] → 文档和 CLI 错误提示明确要求停止 job；清理结果记录删除文件及图存储状态，便于审计和恢复判断。
- [固定默认 seed 造成用户误以为随机] → 普通输出明确打印 seed，支持显式覆盖。
- [CI 解析到非结果日志] → `--ci` 下所有进度和诊断写入 stderr，stdout 保持单一 JSON 文档，并用临时文件 + rename 写结果文件。

## Migration Plan

无需数据迁移。发布后旧命令保持原行为；新增命令先通过测试夹具验证，再在本地使用 `split` 生成子集。回滚只需移除 CLI 分派和辅助模块，不影响已有评测数据库格式。

## Open Questions

无；默认输出路径、seed 和确认开关已在本设计中固定。
