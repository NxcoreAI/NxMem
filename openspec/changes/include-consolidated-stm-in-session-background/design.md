# Design

## Context

The background pipeline uses STM as its sole memory input. This avoids presenting the same evidence once as STM and again as its derived LTM. Conversation Phase 3, however, performs Dreaming immediately and marks source STM as `consolidated` before a later session background is created.

`consolidated` means that an STM has an LTM projection. It does not mean that the STM evidence is rejected, deleted, unauthorized, or no longer relevant to a background window.

## Decision

Define generated STM recall eligibility as every persisted lifecycle state except `deleted`. Admission outcomes such as `write_candidate` and `pending_confirm`, and later states such as `consolidated`, `expired`, `dropped`, or `archived`, remain evidence that `search_context` and the background LLM may rank or discard. The shared lifecycle predicate used by indexing, `search_context`, relation lookup, the background STM selector, and the background analyzer will use this rule.

The legacy STM `hidden` value will no longer act as a recall or background permission gate. New non-rejected STM will be written as `visible`, and startup reconciliation will normalize existing `hidden` STM and create any missing search indexes. `permission-invalid` remains a hard exclusion because it represents revoked source access rather than an admission decision. Owner, source, time-window, candidate-limit, and token-budget controls remain unchanged.

Both fixed maintenance and session dynamic generation use this selector, so they will share the same lifecycle semantics.

The dynamic cache key includes a background selection policy version. This prevents a session created after deployment from reusing an empty cache generated by an older lifecycle or access-state policy.

## Alternatives

### Add LTM to the session background input

Rejected. The background analyzer already receives the source STM. Adding derived LTM would duplicate evidence and require cross-layer deduplication.

### Stop marking source STM as consolidated

Rejected. The lifecycle state is useful for Dreaming and graph maintenance. Background eligibility should not overload general recall lifecycle semantics.

## Risks

- A consolidated STM may also be represented in fixed background text. Existing fixed watermark and dynamic time-window boundaries prevent already-maintained STM from being selected again.
- Older consolidated STM could be reprocessed if its `updatedAt` changes. This is expected because background selection is update-window based.
- Pending or low-confidence STM may reach the background analyzer. This is intentional: the analyzer performs dynamic selection and keeps source citations, while permission-invalid records remain excluded before model invocation.
- Existing session snapshots remain idempotent. A newly created session uses the versioned cache key and does not reuse an active-only dynamic cache.
