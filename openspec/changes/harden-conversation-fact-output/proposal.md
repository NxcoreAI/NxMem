## Why

Agent 对话事实提取目前只要求模型返回 JSON 对象，没有强制 `candidates` 字段结构。模型返回缺少 `candidates` 的对象时，摄入会进入 `fact_pending`，但失败原始响应未持久化，无法区分“没有候选事实”和“模型输出格式错误”，也无法审计重试过程。

## What Changes

- 为对话事实提取请求增加严格 JSON Schema，要求顶层对象必须包含 `candidates` 数组。
- 明确没有候选事实时必须返回 `{"candidates":[]}`，并将其视为正常成功结果。
- 在响应解析或 Schema 校验失败时持久化原始模型响应、失败原因和尝试次数。
- 为每次提取尝试生成独立审计 Trace，避免重试覆盖之前的失败证据。
- 增加格式正确、合法空数组、缺少字段和非法 JSON 的测试。
- 强制逐项抽取对话中的日期、时间、金额、数量、比例、频率和其他数字事实，避免摘要式抽取遗漏操作数。
- 时间轴聚合不得物化合并包含语义时间或数字细节的原子事实，保留各自时间戳和来源。
- 关系判断和最终回答必须区分名称相近但不同的实体，例如 `tennis` 与 `table tennis`。

## Capabilities

### Modified Capabilities

- `context-engine`: 强化对话文档事实提取的结构化输出、空候选语义和失败审计。

## Impact

- 修改对话事实提取请求和 Phase 3 错误处理。
- 复用现有 `llm_fact_fusion_traces` 持久化失败响应，不新增数据库表。
- 不改变候选事实的可信度、准入和 STM/LTM 策略。
